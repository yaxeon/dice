# Roll the dice

Статус: **приложение реализовано и проверено в браузере**. Уточнения пользователя учтены. Установка на реальные телефоны требует публикации по HTTPS и отдельной проверки на устройствах.

## Идея

Небольшое приложение для броска кубиков: чёрный экран, белый кубик в центре. Тап с отпусканием запускает вращение в случайную сторону; движение пальца по свободной области экрана сразу вращает кубики по направлению жеста. После отпускания кубики плавно останавливаются и показывают случайный результат. Приложение можно добавить на домашний экран телефона.

Макет: [mockup.html](./mockup.html). Он показывает пример результата — **5**, один кубик, шесть граней. Переключатели и бросок в макете не работают.

## Стек

| Часть | Решение |
| --- | --- |
| Разметка | HTML5, один экран |
| Стили | CSS, адаптивная компоновка, CSS transforms для кубика |
| Логика | Обычный JavaScript, ES modules |
| Случайность | Web Crypto API: `crypto.getRandomValues()` |
| Установка | PWA: Web App Manifest, иконки, режим `standalone` |
| Работа без сети | Service worker с кешированием файлов приложения |
| Настройки | `localStorage`: количество кубиков и число граней |
| Звук | Web Audio: короткие синтезированные щелчки перекатывания |
| Размещение | Docker с http-server 14.1.1 и Node.js 22 Alpine на порту 80; HTTPS через существующий Traefik |

Для такого объёма достаточно HTML/CSS/JS без фреймворка, сборщика и серверной части. Шрифты и ресурсы — локальные, без зависимости от внешних CDN.

## Экран и управление

- Сплошной чёрный фон `#000`, белые кубики, чёрные точки или цифры.
- Один кубик располагается по центру области броска. Два — по вертикали: сверху и снизу, оба по центру. Три — треугольником: один сверху по центру и два ниже. Размеры и расстояния адаптируются к экрану и оставляют место для вращения.
- На экране нет заголовка и текстовых подсказок. Видны только кубики, SVG-иконки и числа в настройках; доступные описания сохраняются для скринридера.
- Снизу постоянно видны настройки **в один ряд**: SVG-иконка кубиков, `1 / 2 / 3`, вертикальный разделитель, SVG-иконка граней, `4 / 6 / 8 / 10`.
- Видимых текстовых подписей у настроек нет. Иконка с **тремя маленькими кубиками** обозначает количество кубиков, иконка с **одной гранью и шестью точками** — количество граней. Названия групп сохраняются только в доступных описаниях для скринридера.
- Выбранный вариант имеет белую подложку и чёрный текст, остальные — серый текст на тёмной подложке.
- По умолчанию: **1 кубик, 6 граней**. После повторного открытия восстанавливаются выбранные настройки.
- Число граней одинаковое для всех кубиков. Смешанные наборы в первую версию не входят.
- Тап с отпусканием или движение пальца по области броска управляет всеми кубиками одновременно. На компьютере доступны клик и перетаскивание мышью. Взаимодействие с настройками меняет только настройки.
- После изменения настроек предыдущий результат сбрасывается: новые кубики показывают случайные начальные значения и ждут следующего тапа.
- До первого броска уже показываем случайные значения из допустимого диапазона; знак «—» не используется. Скринридер отличает начальные значения от результата завершённого броска.
- В покое и после броска основная грань смотрит прямо на пользователя, **без наклона**. Вращение в трёх измерениях видно только во время жеста и анимации.
- Доступ с клавиатуры: фокус на области броска, Enter или пробел; переключатели — обычные доступные элементы формы.
- Нижняя панель учитывает безопасные отступы телефона; экран адаптируется к портретной и альбомной ориентации.

## Бросок и анимация

### Тап без движения

1. Пользователь касается области броска и отпускает палец. Само касание ещё не запускает бросок.
2. Небольшое дрожание пальца допускается: предлагаем порог перемещения **8 CSS px** для отличия тапа от перетаскивания.
3. После отпускания кубики начинают вращаться в случайном направлении. Для каждого кубика независимо выбирается результат от `1` до выбранного количества граней включительно.
4. Вращение длится примерно **450–650 мс**, с лёгким изменением масштаба и плавной остановкой. Основная грань останавливается прямо перед пользователем, без наклона, и показывает итоговое число.

### Движение пальца

1. Пользователь касается области броска и ведёт пальцем, не отпуская его.
2. После пересечения порога движения кубики **сразу начинают вращаться вслед за пальцем**, ещё до отпускания. Движение вправо или влево задаёт горизонтальное вращение, вверх или вниз — вертикальное; диагональный жест сочетает оба направления.
3. Изменение направления движения сразу меняет направление вращения. Кубики остаются в центре экрана: перемещается палец, сами кубики только вращаются.
4. При отпускании продолжаем вращение по последнему направлению движения и плавно замедляем его примерно за **450–650 мс**. Скорость движения пальца может влиять на начальную скорость продолжения вращения, с ограничением максимальной скорости.
5. В момент отпускания независимо генерируем результат для каждого кубика; по завершении вращения показываем его на основной грани. Если палец остановился перед отпусканием, сохраняем последнее направление и используем небольшую скорость продолжения вращения.

Тап и перетаскивание завершаются **одним броском**. Итоговое число остаётся до следующего броска или смены настроек. Повторение предыдущего числа допустимо: это обычное свойство случайных бросков, исключать повторы не будем.

### Обработка жестов

- Объединяем касания и мышь через Pointer Events; отслеживаем только один активный палец или указатель.
- Начатый в области броска жест продолжаем отслеживать через захват указателя, даже если палец или мышь выходит за её границы. Жест, начатый на настройках, не вращает кубики.
- Для области броска отключаем стандартную обработку жеста браузером через `touch-action: none`, чтобы движение пальца управляло кубиками, а не прокруткой страницы.
- Не создаём дополнительный бросок из события клика после отпускания пальца или мыши.
- При отмене жеста системой (`pointercancel`) возвращаем кубики к предыдущему состоянию без нового результата и освобождаем управление.
- Повторные касания и второй палец во время активного жеста или завершающей анимации игнорируются. Настройки временно недоступны от начала жеста до его завершения.
- Enter или пробел запускают сценарий обычного тапа.

При системной настройке `prefers-reduced-motion` вращение, включая вращение во время движения пальца, заменяется небольшим изменением прозрачности. Результат появляется после отпускания. Доступное текстовое описание сообщает результат каждого кубика после завершения броска.

### Звук

Звук перекатывания начинается с первого кадра анимации броска после отпускания пальца или мыши: негромкие короткие щелчки с небольшими вариациями высоты замедляются и затихают вместе с анимацией. Во время перетаскивания до отпускания звука нет. Завершение броска и скрытие страницы останавливают звук. При загрузке, отмене жеста и смене настроек звука нет.

Web Audio создаётся и разблокируется действием пользователя. Аудиофайлы и внешние сервисы не нужны; звук доступен без сети. Ограничения браузера на звук не мешают броскам. Параметры звука не влияют на результат кубиков.

## Случайность

Используем `crypto.getRandomValues()`: браузер предоставляет криптографически стойкий генератор, использующий энтропию платформы. Это подходящий источник непредсказуемых чисел для кубиков, но не обещание физического генератора «истинной случайности». [Документация Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues).

Чтобы все грани имели одинаковую вероятность, преобразуем случайное 32-битное значение через **отбрасывание лишнего диапазона** (rejection sampling). Особенно это важно для 6 и 10 граней: прямой остаток от деления всего диапазона даёт небольшой перекос.

Координаты, направление, скорость и время жеста не используем как источник результата: сами по себе они не гарантируют дополнительную случайность. Движение пальца управляет только анимацией; при обычном тапе направление вращения выбирается случайно. Итоговое число независимо от жеста и предыдущего результата. Если Web Crypto недоступен, показываем понятное сообщение об ошибке.

## Вид кубиков — предложение для первой версии

- Грани кубиков имеют **острые края, без закруглений**: соседние грани соединяются без чёрных зазоров в углах.
- **6 граней:** привычные точки на белом кубике; результат читается на основной, обращённой к пользователю грани.
- **4, 8 и 10 граней:** та же белая форма, крупная цифра на основной грани; диапазоны соответственно `1–4`, `1–8`, `1–10`.
- Форма служит визуальным представлением результата; физическую симуляцию столкновений и отскоков не моделируем.

**Согласованное решение:** для d4, d8 и d10 используем ту же форму кубика с цифрой; для d6 — точки.

## Добавление на домашний экран

- PWA открывается по HTTPS и после установки запускается в отдельном окне в режиме `standalone`.
- Manifest задаёт название, адрес запуска, чёрный фон и иконки 192×192 / 512×512; также добавим maskable-иконку и `apple-touch-icon` 180×180.
- На Android установка доступна через меню поддерживаемого браузера. На iPhone базовый сценарий — Safari → «Поделиться» → «На экран Домой». Интерфейс установки зависит от браузера и версии ОС. [Установка PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).
- Service worker кеширует необходимые файлы; после первого успешного открытия и завершения кеширования броски работают без интернета.
- Все ресурсы и генерация результата находятся на устройстве; подключения к серверу для броска не требуется.
- Будущая инструкция по установке будет в README, чтобы сохранить на основном экране только две настройки.

## Критерии проверки

- Все 12 сочетаний количества кубиков и граней дают нужное число результатов в допустимом диапазоне; для d10 верхний результат — именно 10.
- Отдельная проверка генератора на границах диапазона и отбрасывании лишних значений; небольшой тест частот — дополнительная диагностика, а не доказательство случайности.
- Тап с отпусканием даёт один бросок в случайном направлении; дрожание в пределах порога не превращает тап в перетаскивание.
- При перетаскивании кубики вращаются ещё до отпускания, следуют за направлением пальца, поддерживают диагональ и смену направления; после отпускания продолжают движение и показывают случайный результат.
- Выход указателя за область броска, отмена жеста, пауза перед отпусканием и второй палец не оставляют приложение в состоянии незавершённого броска.
- Тап и движение пальца по настройкам не бросают кубики, отпускание после перетаскивания не вызывает повторный бросок, быстрые повторные тапы не запускают параллельные анимации.
- Настройки восстанавливаются, изменение настроек сбрасывает результат и создаёт случайные начальные значения; интерфейс работает и при недоступном хранилище.
- При открытии нет знака «—», начальные значения допустимы. Завершённый бросок показывает результат на ровной, обращённой к пользователю грани.
- На узких экранах от 320 px и в альбомной ориентации кубики и обе группы настроек видны без горизонтальной прокрутки.
- Проверка клавиатуры, озвучивания результатов и режима уменьшенной анимации.
- На реальных iPhone/Safari и Android/Chrome: добавление на домашний экран, запуск из иконки и бросок без сети после кеширования.

## Результаты проверки

- Проверены модульные тесты генератора, настроек, жестов и остановки вращения.
- В браузере проверены все 12 сочетаний количества кубиков и граней, включая выпадение 10 на d10.
- Компоновки с 1/2/3 кубиками проверены при 390×844, 320×568 и 844×390: горизонтальной и вертикальной прокрутки нет.
- Проверены случайные начальные значения, ровная грань после броска, восстановление настроек после перезагрузки, перетаскивание, клавиатура, отпускание вне области броска и отсутствие лишних бросков при быстрых тапах или жесте на настройках.
- Локальный сервер был остановлен: приложение успешно перезагрузилось из кеша и выполнило бросок. Затем сервер снова запущен.
- Контейнер с http-server собран и проверен на порту 4175: healthcheck получил статус `healthy`, все ресурсы отдаются с корректными MIME-типами и `no-store`, листинг каталогов отключён, отсутствующие файлы возвращают 404. После остановки контейнера приложение перезагрузилось из офлайн-кеша и выполнило бросок.
- Реальные iPhone/Android, установка из меню браузера и системный режим уменьшенной анимации на устройстве пока не проверялись. Обработка отмены жеста реализована; системное прерывание на реальном телефоне также требует проверки.

Для проверки установки на телефонах нужен опубликованный HTTPS-адрес. Для сервера пользователя подготовлен Dockerfile, совместимый с его `docker-compose.yml`: приложение обслуживается http-server 14.1.1 на порту 80, Traefik обеспечивает HTTPS для `dice.yaxeon.ru`. HTTP-кеш и листинг каталогов отключены; офлайн-кеш service worker сохраняется. Пакет устанавливается только в контейнер при сборке, локальный запуск остаётся на Python. Команда запуска приведена в README.
